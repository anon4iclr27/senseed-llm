# How the four schemes are implemented

All schemes compress only the seven projection matrices of each decoder layer
(`q,k,v,o,gate,up,down`). Embeddings, the LM head and norms stay in
full precision. Every compressed checkpoint is written back as a drop-in Hugging
Face checkpoint (`experiments/compress_checkpoint.py`) and scored by the same
code (`experiments/eval_hf.py` for WikiText-2 perplexity, 2048-token windows;
`scripts/run_lm_eval.sh` for zero-shot accuracy), so all differences come from
the weights alone.

| Scheme | Entry point | Calibration data | Code |
|---|---|---|---|
| Unquantized (BF16) | `run_pipeline.sh <model> bf16` | – | original checkpoint, loaded with `dtype=bfloat16` |
| SeedLM | `compress_checkpoint.py --method seedlm` | none | `senseed/codec/seedlm.py`, `prune.py` |
| S-Quant | `compress_checkpoint.py --method squant` | none | `senseed/codec/squant.py` |
| SenSeed | `compress_checkpoint.py --method senseed`; `scripts/joint_allocate.py` | none | `senseed/codec/allocate.py`, `senseed/sensitivity/` |

## Unquantized (BF16)
The reference. No compression step: the downloaded model is evaluated with
`--dtype bfloat16` (perplexity) and `dtype=bfloat16` (lm-eval).

## SeedLM
Re-implementation of the seed-based scheme: each weight matrix is split into
blocks of `B=8` weights; a block is `w ≈ U(s) t`, where `U(s)` is a `B×k` matrix
generated by a maximal-length `S`-bit LFSR started at seed `s` (`lfsr.py`) and
`t` holds `k` least-squares coefficients quantised to `m`-bit mantissas with one
shared `e`-bit exponent per block (`quant.py`). The encoder searches all
`2^S − 1` seeds for the smallest quantised error. The 4-bit point is
`(S,k,m,e) = (16,3,4,4)`, i.e. `(S + m·k + e)/B = 4.0` bits/weight
(`SEEDLM_4BIT`). `prune.py` implements an exact projection-based shortlist that
keeps the seed search tractable for 7B+ models. GPU search: `codec/gpu.py`.

## S-Quant
Re-implementation of adaptive-basis seed compression: block size `B=16`,
`S=16`-bit seeds, and the number of bases `k` per block is the smallest `k`
whose explained-energy ratio reaches `R_th` (default 0.90, `--squant-rth`);
coefficients are int8 with one FP16 scale per `G=8` blocks. Seed and `k` are
chosen on unquantised energy first, coefficients are quantised afterwards.
The rate follows the published Eq. 13; the paper's discussion notes that it
omits the per-block `k` signalling cost.

## SenSeed
Same seed/coefficient format as SeedLM; only the per-block bit allocation
changes, and it is derived from what the decoder already holds:

1. **Data-free importance** (`senseed/sensitivity/actscale.py`, `blockmap.py`):
   input second moment `a_j ≈ γ_j²` from the RMSNorm gains for
   q/k/v/gate/up; one propagation hop for `o_proj` and `down_proj`
   (Gauss–Hermite quadrature for `E[silu(g)²]`). Input channels are sorted by
   `a` before blocking, and block importance is the block mean of `a`,
   normalised to unit mean per tensor.
2. **Allocation.** `--method senseed` (in `compress_checkpoint.py`) uses a
   schedule in which `k ∈ [2,6]` follows a fixed function of the importance
   (slope `--slope`, mean rate fixed at 4.0 bits/weight). `scripts/joint_allocate.py`
   implements the rate–distortion variant over the `(S,k)` grid: it takes the
   lower convex hull of the measured per-configuration excess loss, and assigns
   each block the hull point selected by `imp · slope ≥ λ`, with `λ` bisected so
   the mean rate meets the target. The uniform arms feeding the damage curve are
   built with `scripts/make_uniform.py`.
3. **No side information.** Since the importance is recomputable from the
   checkpoint, the decoder reproduces every block's `(S,k)`;
   `tests/test_allocation.py` checks that the allocation does not depend on the
   block's own weights.
